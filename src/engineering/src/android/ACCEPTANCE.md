# SoundField 上位机验收表

在每项前的方框打勾；失败时记录手机型号、Android 版本、操作步骤、页面错误信息，以及 Zynq 或模拟服务日志。**模拟服务通过不代表真实硬件已通过。**

旧版曾通过 Debug APK 构建、Android 单元测试与 Python 模拟服务测试；模拟器中曾完成设备 WAV 下载、试听和重启恢复。改为**手机端实时 PCM 录音**后，以下录音项目尚待用户连接手机和真实 Zynq 验收；增益效果和 30 分钟连续运行也待实测。当前 App 仅保留以太网通信。不要把此前设备 RAM 录音或模拟服务结果记作本次手机录音通过。

## 准备

1. 安装 `app/build/outputs/apk/debug/app-debug.apk`。首次试听把手机媒体音量调低。
2. 电脑在项目根目录运行：

   ```powershell
   py -3 tools\mock_zynq.py --host 0.0.0.0 --port 7000 --audio-port 9000 --http-port 8000
   ```

3. 真机与电脑同网时，用 `ipconfig` 查电脑可达的 IPv4，填入 App「通信」页。电脑防火墙允许 TCP 7000、9000、8000。模拟器测试可改用 `127.0.0.1`、选择「系统默认路由」，并运行：

   ```powershell
   adb reverse tcp:7000 tcp:7000
   adb reverse tcp:9000 tcp:9000
   adb reverse tcp:8000 tcp:8000
   ```

4. 每次改模拟服务启动参数，先停止旧进程再重新运行；新启动的模拟服务中始终有 `demo_440hz.wav`。

## 与 Zynq 固件对齐的接口

- 控制消息为 UTF-8 NDJSON v1，每条以 `\n` 结束，单条最多 2048 字节。请求和响应的 `id` 对应。
- `GET_INFO.data` 使用 `device_name`、`firmware_version`、`protocol_version=1`、`sample_rate_hz=48000`、`simulated`、`capabilities.stream_audio`、`capabilities.file_download`、`capabilities.gain_control`。旧固件未声明 `gain_control` 视为不支持。
- `gain_control=true` 时以太网连接后请求 `GET_FILTER_STATUS`，其成功 `data.gain_db` 必须是 0–96 整数；用户在「录音」页解锁后滑动或输入有效值时发送 `SET_FILTER_GAIN` 和 `args.gain_db`，成功响应必须返回设备实际采用的 `data.gain_db`。锁定后不接受新修改；默认 0 dB；拒绝时返回标准 `error.code` 和 `error.message`。高增益可能使 16 位 PCM/WAV 削波。
- `LIST_RECORDINGS.data.recordings` 中每项含非空 `id`、`filename`、整数 `size_bytes`。HTTP GET `/api/recordings/{id}` 返回对应完整 WAV；若列表数量增加到单条 JSON 超过 2048 字节，需要与固件侧共同确定分页协议。
- `START_STREAM` 返回 `sample_rate_hz=48000`、`channels=1`、`bits_per_sample=16`、`encoding="S16LE"`、`port`；音频端口只发送连续原始 PCM 字节。
- 手机录音复用 `START_STREAM` 的 TCP PCM，边接收边写手机 WAV；停止录音且没有实时试听时发送 `STOP_STREAM`。录音按钮不使用旧 `START_RECORD`/`STOP_RECORD`；`GET_STATUS.recording`、`file_download` 和 HTTP 8000 均不是手机录音的前提。旧固件若 `stream_audio=false`，手机录音按钮禁用。单个 WAV 当前上限约 2 GB。
- 角度统一采用 **0° 正右方、逆时针递增**。App 直接显示与发送协议角度，未对数值另做旋转。
